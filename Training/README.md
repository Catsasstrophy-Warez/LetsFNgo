# Training Nexus's own model

This directory turns the simulator-generated dataset (`docs/TRAINING_DATA.md`) into a fine-tuned open model. You train it with LoRA through [mlx-lm](https://github.com/ml-explore/mlx-lm) on an Apple silicon Mac, score it with the Swift evaluator, and ship it only if the promotion gate passes. This is the L2 tier in `docs/APPLE_PLATFORM_NOTES.md`.

| File | What it does | Runs on |
|---|---|---|
| `prepare.py` | NexusDatasetGen JSONL → mlx-lm `train/valid/test.jsonl` (chat or completions) | anywhere (standard library only) |
| `lora.yaml` | `mlx_lm.lora` hyperparameters and the base model | Mac |
| `train.sh` | `mlx_lm.lora` train → test → `mlx_lm.fuse` | Mac (Apple silicon) |
| `evaluate.py` | Runs the model on the eval split and writes predictions for the Swift evaluator | Mac; `--responses` mode anywhere |
| `test_training.py` | Unit tests: `python3 -m unittest discover Training` | anywhere |
| `smoke.sh` | The Linux CI check: generate → prepare → round trip → evaluator → gate | anywhere with Swift |

Work files go to `Training/build/`, which git ignores.

## 0. Prerequisites and the licence check

You need:
- an Apple silicon Mac with 16 GB or more (32 GB is comfortable for a 1.7B model at `max_seq_length: 4096`)
- Xcode with Swift 6.2 or later
- Python 3.10 or later

```sh
python3 -m venv .venv && source .venv/bin/activate
pip install "mlx-lm>=0.31" huggingface_hub
```

**Check the base model's licence before training, and record it.** The weights we ship are a derivative of the base model.

```sh
BASE=Qwen/Qwen3-1.7B     # must match `model:` in Training/lora.yaml
python3 - "$BASE" <<'PY'
import sys
from huggingface_hub import model_info
info = model_info(sys.argv[1])
licence = (info.card_data or {}).get("license") if info.card_data else None
print("model:", info.id, "revision:", info.sha, "licence:", licence, "gated:", info.gated)
allowed = {"apache-2.0", "mit", "bsd-3-clause", "bsd-2-clause"}
sys.exit(0 if licence in allowed else 1)
PY
```

- A non-zero exit means the licence is not on the allow list. Stop, read the model's licence text and get sign-off before going on. Custom licences (Llama, Gemma and others) carry use restrictions and attribution duties.
- Keep the printed `revision`: it becomes `--base-version` in step 5, so the registry knows exactly which weights the adapter was trained on.
- For the Core AI path (step 6), also pick a base model the Core AI registry supports: `uv run coreai.model.registry --list-models`, from Apple's `coreai-models`.
- The dataset itself is generated by our simulators, so it carries no third-party licence.

## 1. Generate the dataset

Use a release build for large runs (about 5 examples a second in debug).

```sh
mkdir -p Training/build
swift build -c release --product NexusDatasetGen
swift run -c release NexusDatasetGen --count 5000 --seed 42 --domain mixed --out Training/build/train.jsonl
swift run -c release NexusDatasetGen --count 500 --seed 42 --domain mixed --split eval --out Training/build/eval.jsonl
```

- `--domain` selects the simulators:
  - `loop` (the default) gives the instrument-loop diagnoses, tool transcripts and ladder questions.
  - `automotive` gives only charging-system cases (`chargingDiagnosis`, from `NexusAutomotive`).
  - `mixed` interleaves one charging case after every four loop examples.
- The train and eval splits draw from disjoint seed ranges, so no scenario is in both.

## 2. Convert for mlx-lm

```sh
python3 Training/prepare.py --train Training/build/train.jsonl --eval Training/build/eval.jsonl --out Training/build/data
```

This writes `train.jsonl`, `valid.jsonl` and `test.jsonl`:
- **The generator's splits are preserved.** Every eval example goes to `test.jsonl` and nowhere else. A stable hash of each train example's id sends 10 % of them to `valid.jsonl` (`--valid-fraction`).
- **The default `--format chat`** writes `{"messages": [system, user, assistant]}`. The user turn holds the question, every known value with its truth class, the tests and the candidate causes.
- **Tool transcripts** keep their real `search_objects` / `related_objects` / `get_measurements` calls in the OpenAI `tool_calls` format, plus a `tools` list. Use `--tool-style text` for a base model whose chat template has no tool support.
- **The assistant target** is the reference answer, then `CAUSE: <label>` and, when there are tests, `NEXT_TEST: <title>`. `evaluate.py` parses those two lines back out.

## 3. Fine-tune with LoRA and fuse

```sh
Training/train.sh                       # full run from Training/lora.yaml
ITERS=50 Training/train.sh              # smoke run
MODEL=mlx-community/Qwen3-1.7B-4bit DEQUANTIZE=1 Training/train.sh   # QLoRA on a 4-bit base, fused back to full precision
```

`train.sh` runs three commands, all of which exist in mlx-lm 0.31:

```sh
mlx_lm.lora --config Training/lora.yaml --model "$MODEL" --train --data Training/build/data --adapter-path Training/build/adapters
mlx_lm.lora --config Training/lora.yaml --model "$MODEL" --test  --data Training/build/data --adapter-path Training/build/adapters
mlx_lm.fuse --model "$MODEL" --adapter-path Training/build/adapters --save-path Training/build/fused [--dequantize]
```

- `lora.yaml` uses LoRA rank 16 on the last 16 blocks, AdamW, cosine decay from 1e-4 over 2000 iterations, and `mask_prompt: true`, so the loss covers only the final assistant message.
- Flags on the command line override the file.
- Watch the validation loss that `steps_per_eval` reports. If it rises while the training loss falls, lower `iters` or raise `dropout`.

## 4. Evaluate with the Swift evaluator

```sh
python3 Training/evaluate.py --model Training/build/fused --examples Training/build/eval.jsonl \
    --out Training/build/predictions.jsonl --template-kwargs '{"enable_thinking": false}'
swift run -c release NexusDatasetGen evaluate --examples Training/build/eval.jsonl \
    --predictions Training/build/predictions.jsonl --out Training/build/candidate.json
```

- `evaluate.py` decodes greedily with the model's chat template. It turns the `CAUSE:` and `NEXT_TEST:` lines into `predictedCause` and `predictedNextTest`, and passes the rest through as `answer`. That is the `ModelPrediction` format in `Sources/NexusTrainingData/Evaluator.swift`.
- `--adapter-path Training/build/adapters` with `--model <base>` evaluates the adapters without fusing.
- `--template-kwargs` is for Qwen3; drop it for models without a thinking mode.

The evaluator reports:
- `rootCauseAccuracy`
- `nextTestAgreement`
- `hallucinatedValueRate`: numbers that are not in the example
- `truthClassDiscipline`: cited values without their truth class count against it

It also breaks accuracy down per example kind. Tool-call validity is measured by the Swift agent evals.

For a first model, score the trivial baseline as the model to beat:

```sh
swift run -c release NexusDatasetGen baseline --train Training/build/train.jsonl --examples Training/build/eval.jsonl --out Training/build/baseline.jsonl
swift run -c release NexusDatasetGen evaluate --examples Training/build/eval.jsonl --predictions Training/build/baseline.jsonl --out Training/build/baseline.json
```

## 5. Promotion gate and model registry

```sh
# The current model's metrics: baseline.json for the first model, otherwise the registry entry's metrics.
swift run -c release NexusDatasetGen gate --candidate Training/build/candidate.json --current Training/build/baseline.json

swift run -c release NexusDatasetGen register --registry Training/models.json \
    --id nexus-mlx-2026.09.1 --kind mlxWeights \
    --base-model Qwen/Qwen3-1.7B --base-version <revision from step 0> \
    --artifact Training/build/fused --metrics Training/build/candidate.json
```

- **`gate`** exits 0 only if the candidate is at least as good on every metric and strictly better on one. Lower is better for `hallucinatedValueRate`.
- **`register`** fingerprints the artifact: SHA-256 and size, and for a directory, a digest over its files. It runs the same gate against the newest registry entry for that base model and kind, and writes the manifest only if the candidate passes. A refusal exits 1 and leaves the current model in place.
- The manifest format is `ModelRegistry` (`docs/TRAINING_DATA.md`, "Model registry and gate").
- `NexusDatasetGen gate-selfcheck --train … --examples …` proves the gate itself works on real evaluator output. CI runs it.

## 6. Export for Core AI (when `coreai-models` supports it)

This step is blocked for now. Apple's `coreai-models` package doesn't build for the iOS Simulator (issue #49) and has no Xcode 27 release (issue #293); see `docs/APPLE_PLATFORM_NOTES.md`. When it builds:

1. Fuse a full-precision model (`DEQUANTIZE=1` if you trained on a quantized base).
2. Export it to a Core AI model per platform: `uv run coreai.llm.export …`. Take the flags from that package's `--help`, because its CLI isn't stable yet.
3. Register the exported `.aimodel` as its own registry entry. Use the same `--metrics` only after re-running step 4 against the exported model, since conversion can change outputs.
4. Load it in the app through `CoreAILanguageModel` inside `FoundationModelsProvider`. Only a model with tool calling can run agent tools; the stock adapter lacks it, and the community `coreai-kit` adds it.

## What CI checks

The Linux job runs `Training/smoke.sh`. It makes a 20 + 10 example mixed dataset and runs these Python tests over it. It then feeds the reference answers through `evaluate.py` as a stand-in model and scores them with the Swift evaluator. The gate must promote them over the baseline, refuse the reverse, and pass `gate-selfcheck`. Training itself needs Apple silicon and doesn't run in CI.
